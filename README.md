# RdpMouseBridge

用 Windows 自带 MSTSC 远程玩 3D 游戏时，RDP 只把光标的**绝对位置**送进远程会话，而大多数游戏的视角旋转只读 **Raw Input 的相对位移 ΔX/ΔY**，于是相机不动。

RdpMouseBridge 是一个图形化的小工具：

- **客户端**（你面前的电脑）：用 `WM_INPUT` 读取物理鼠标的原始相对位移，通过 UDP 发给游戏 PC。只在 mstsc 前台时转发，默认开启。
- **服务端**（游戏 PC）：收到位移后用 `SendInput(MOUSEEVENTF_MOVE)` 注入当前会话。并且可以**检测游戏窗口，把鼠标限制在游戏窗口内或屏幕中心的一个小范围里**，避免 RDP 绝对光标和注入位移一起把鼠标带得满屏乱飘。

两个角色在同一个 exe 里，用标签页切换。按键、滚轮仍然由原版 RDP 处理，本工具只补“移动 → 视角”这一条链路。

> 免工具试法：本地客户端如果是 Windows 11 24H2+，可以在 `.rdp` 文件末尾加 `allowrelativemousemode:i:1` 再连接。部分环境直接有效；Windows 10 的 mstsc 不支持这个键。

## 编译

```powershell
cd RdpMouseBridge
.\build.ps1
```

生成 `RdpMouseBridge.exe`（WinForms GUI，.NET Framework 4.x，无需安装额外依赖）。

## 使用

两台电脑需要能互通 UDP，默认端口 50505，建议在同一局域网。第一次启动服务端时 Windows 防火墙会弹窗，允许“专用网络”；跨公网请放行 UDP 或使用 Tailscale / ZeroTier。

### 游戏 PC（服务端）

1. 右键 `RdpMouseBridge.exe` → 以管理员身份运行（如果游戏本身是管理员权限，这一步是必须的，否则 UIPI 会拦截注入）。
2. 切到“服务端”标签页，设置 UDP 端口（和客户端一致）。
3. 游戏检测：
   - **始终转发**：勾选后跳过前台检测，全局始终生效（开启后“自动检测”与“指定进程名”会自动置灰不可选）。适合多开、特殊窗口或不需要进程匹配的场景。
   - **自动检测全屏游戏**：当最前面的窗口铺满整个显示器时，认为它是游戏。
   - **指定进程名**：输入游戏进程名，例如 `game.exe`。窗口不是全屏、或者自动检测不准时用这个。
4. 鼠标限制策略：
   - **鼠标限制总开关**：
     - **关闭（默认）**：纯相对位移注入，不调用任何 `ClipCursor` 或光标居中锁定。**原神等免限制游戏直接保持关闭即可流畅游玩！**
     - **开启**：针对聚焦时被游戏自身限制卡死的 3D 游戏，可激活下方策略：
       - **强制解除限制（推荐）**：持续清除游戏自身调用的 `ClipCursor` 限制，破除画地为牢。
       - **限制在屏幕中心区域**：把光标限制在游戏窗口中心的一个小方块里（默认 400px）。
       - **限制在游戏窗口客户区**：限制在整个游戏画面内。
       - **不干涉**：保持系统默认。
       - **注入后光标实时锁在中心**：注入相对位移后即刻居中，避免光标撞到屏幕边缘导致卡死。
5. 点“启动服务端”。状态区会显示收包/注入数量，以及当前检测到的游戏和限制状态。

游戏切换走（Alt+Tab）、停止服务端或关闭窗口时，鼠标控制与限制会**自动解除**，不会锁住整个桌面。菜单/背包需要鼠标指针时，按客户端热键 `Ctrl+Alt+M` 暂停转发即可自由移动指针。

### 关于 Minecraft（我的世界）视角乱飘的说明

* **现象与原因**：Minecraft (Java 版) 底层使用 GLFW / LWJGL 引擎。当本地鼠标聚焦在 RDP 窗口内时，RDP 客户端会向远端注入**绝对坐标**，触发 GLFW 著名的 RDP 绝对坐标计算 Bug（官方缺陷编号 **MC-126875**），导致视角剧烈反弹乱飘；而当本地鼠标点在 RDP 窗口外（如客户端桌面）时，RDP 停止发送绝对坐标，远端仅接收 `RdpMouseBridge` 的纯净相对位移，所以视角瞬间顺畅。
* **最佳解决方案**：
  1. **安装 Minecraft RDP 专用模组**（最推荐）：在客户端或服务端 Minecraft 中安装 **`[MR] True RDP Fix` (MrTrueRdpFix)** 或 **`RDPMouse`**（支持 Fabric / NeoForge / Forge），可从底层直接彻底修复 GLFW 的 RDP 绝对坐标冲突，无需任何变通操作。
  2. **客户端非前台转发技巧**：在客户端取消勾选“仅在 mstsc 前台时转发”，将本地鼠标停留在客户端桌面或辅助窗口上，同样可获得丝滑视角。

### 你面前的电脑（客户端）

1. 先用 mstsc 正常连上游戏 PC。
2. 运行 `RdpMouseBridge.exe`，在“客户端”标签页填入游戏 PC 的 IP 和端口，点“启动客户端”。
3. 点回 mstsc 窗口移动鼠标；客户端状态里的“转发”应为“是”，“已发送”会增长。
4. 按 `Ctrl+Alt+M` 可随时暂停/恢复转发。

默认勾选“仅在 mstsc 前台时转发”。取消勾选则会一直转发（适合非常规窗口场景，但离开 mstsc 后鼠标移动也会传给游戏）。

## 参数说明

客户端：
- **灵敏度**：位移倍数，默认 1.00。
- **转发频率**：每秒发送多少批位移，默认 250Hz；高刷 FPS 可试 500。

服务端：
- **dry-run**：只统计收包，不注入输入，适合先验证网络。

## 配置保存（JSON 持久化）

- 软件在**关闭窗口**或**点击启动服务端/客户端**时，会自动将当前的所有配置保存为同目录下的 `config.json`。
- 下次打开程序会自动恢复上次的所有参数（包括当前选中的标签页、游戏 PC IP、端口、灵敏度、进程名、始终转发、限制策略等）。
- 若程序运行在受权限保护的目录（如 `Program Files`），则会自动安全回退保存到 `%APPDATA%\RdpMouseBridge\config.json`。也可以随时手动用记事本编辑该 JSON 文件。

## 注意

- `SendInput` 是合成输入，少数内核级反作弊可能拦截甚至判定异常；建议先单机/私人服务器验证，风险自负。
- 鼠标范围限制使用 `ClipCursor`。游戏窗口本身也用鼠标时（菜单、背包），可临时关掉“限制”或按 Alt+Tab 让游戏失焦，限制会立即解除。
- 客户端默认只给 `mstsc.exe` 转发；如果你用新版 Windows App（msrdc）等客户端，可取消“仅在 mstsc 前台”并自行控制。
- UDP 不保证送达，丢包只影响个别帧的视角。
- 客户端必须是 Windows。
